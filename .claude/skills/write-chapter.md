# 写作技能：Linux 内核修仙传章节编写

## 写作铁律

### 1. 开篇法则
- **底层切入**：从最朴素的场景写起，不用术语堆砌
- **先情感后技术**：先让读者关心角色，再引入技术内容
- **第一句就有钩子**：用冲突、悬念或反差抓住读者

### 2. 升级节奏
- 间隔呈**指数增长**：初期快给甜头，后期慢造稀缺
- **3-5 章一个小高潮**，**20-30 章一个大转折**
- 每次突破遵循：**瓶颈 → 积累 → 机缘 → 突破 → 降级重启**
- 突破必须有**具体技术难题**作为瓶颈，不能空洞地"闭关"

### 3. 打脸/爽点设计
采用"蓄压-释放"循环：
```
嘲讽铺垫 → 主角隐忍 → 技术碾压 → 围观震惊
```
每次循环提升围观者层次：同学 → 导师 → 公司 → 业界 → 内核社区 → Linus

### 4. 伏笔设计
- **超级伏笔**：贯穿全书的线索（如前传中的 `#ifdef 0` 代码）
- **中级伏笔**：跨卷线索（某句话在数卷后才被理解）
- **微型伏笔**：单卷内的暗示（进程名、日志消息、配置注释）
- **铁律**：伏笔不要直接标出来，自然融入叙述

### 5. 技术与叙事融合
- 技术内容通过**剧情冲突**引入，不是平铺直叙
- 每个技术概念都有**顿悟时刻**：卡壳 → 理解 → 豁然开朗
- 生活流与技术流交替：不要连续多章纯技术
- 用**修仙隐喻**包装技术概念，但技术细节必须准确

## 使用方式

当用户要求编写新章节时：
1. 先读取 `docs/refs/修仙技法蒸馏.md` 了解完整技法
2. 读取相关卷的 `index.md` 了解本卷大纲
3. 读取前一章了解上下文
4. 读取 `docs/guide/character-guide.md` 和 `docs/guide/world-building.md` 确保一致性
5. 按照上述格式和铁律编写章节
6. 确保技术内容准确，修仙隐喻恰当
7. 在道藏笔记中自然融入伏笔（不要标注"伏笔"）
