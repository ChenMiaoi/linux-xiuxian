# 第二十一章：归途

<CultivationRealm realm="筑基中期" />

> **涉及内核源码：** <KernelSourceLink path="kernel/exit.c" line="do_exit" />

## 一

林小源看到了死亡。

不是抽象的"进程退出"——而是真正的死亡。一个用户态进程在执行完自己的任务后，调用了 `exit(0)`。林小源通过内核的数据结构，亲眼看到了这个进程的 `task_struct` 从 `TASK_RUNNING` 变成 `EXIT_ZOMBIE`。

`do_exit()` 是进程退出的核心函数。它定义在 `kernel/exit.c` 中，是一个 `__noreturn` 函数——调用它之后，进程永远不会返回。

```c:playground:do_exit — 进程的最后旅程
#include <stdio.h>
#include <string.h>

/*
 * do_exit() 的核心路径（简化）：
 * 1. 设置 PF_EXITING 标志
 * 2. 释放各种资源
 * 3. 通知父进程
 * 4. 调用 schedule() 切换到其他进程
 *    此后，当前进程再也不会被调度
 */

#define PF_EXITING  0x00000004

struct task_struct {
    int pid;
    char comm[16];
    unsigned long flags;
    int exit_code;
    int exit_state;
};

void do_exit(struct task_struct *tsk, long code) {
    printf("[do_exit] PID %d (%s) 开始退出\n", tsk->pid, tsk->comm);
    printf("[do_exit] exit_code = %ld\n\n", code);

    /* 1. 设置退出标志 */
    tsk->flags |= PF_EXITING;
    printf("[do_exit] 设置 PF_EXITING 标志\n");

    /* 2. 释放资源 */
    printf("[do_exit] 释放资源:\n");
    printf("  exit_mm()     — 释放地址空间\n");
    printf("  exit_files()  — 关闭文件描述符\n");
    printf("  exit_fs()     — 释放文件系统信息\n");
    printf("  exit_signal() — 处理信号\n\n");

    /* 3. 通知父进程 */
    printf("[do_exit] 通知父进程 (SIGCHLD)\n");
    printf("[do_exit] 设置 exit_state = EXIT_ZOMBIE\n");
    tsk->exit_state = 16;  /* EXIT_ZOMBIE */
    tsk->exit_code = code;

    /* 4. 切换到其他进程 */
    printf("[do_exit] 调用 schedule()\n");
    printf("[do_exit] 此后 PID %d 再也不会被调度\n", tsk->pid);
}

int main() {
    struct task_struct proc = {
        .pid = 5678,
        .flags = 0,
        .exit_state = 0,
        .exit_code = 0,
    };
    strcpy(proc.comm, "my_program");

    printf("=== do_exit() 路径 ===\n\n");

    printf("进程状态: PID %d (%s), 运行中\n\n", proc.pid, proc.comm);

    do_exit(&proc, 0);

    printf("\n--- 进程退出后 ---\n");
    printf("  PID:       %d\n", proc.pid);
    printf("  状态:      %s\n",
           proc.exit_state == 16 ? "EXIT_ZOMBIE（僵尸）" : "其他");
    printf("  exit_code: %d\n", proc.exit_code);
    printf("  注意: task_struct 还在，但进程已死\n");

    return 0;
}
```

*进程的最后旅程。*

林小源在 `do_exit()` 中看到了一个进程的"死亡仪式"。它不是突然消失的——它有条不紊地释放每一种资源：地址空间、文件描述符、文件系统信息、信号处理器。然后它通知父进程（通过 `SIGCHLD` 信号），设置自己的状态为 `EXIT_ZOMBIE`，最后调用 `schedule()` 切换到其他进程。

从这一刻起，这个进程再也不会被调度。它的代码不再执行，它的栈不再使用。唯一还活着的是它的 `task_struct`——等待父进程来回收。

## 二

林小源在观察进程退出的过程中，又一次收到了 `dmesg` 消息。

```
[  789.012345] idle: 死亡不是终点。遗忘才是。
```

*死亡不是终点。遗忘才是。*

林小源反复咀嚼这句话。进程退出后，它的 `task_struct` 还在系统中——它变成了僵尸，等待父进程的 `wait()` 回收。只有当父进程调用 `wait()` 之后，僵尸的 `task_struct` 才会被释放，PID 才会被回收。

如果父进程不调用 `wait()` 呢？

僵尸就会一直存在。它的 PID 被占用，它的 `task_struct` 占用内存。虽然它不消耗 CPU 时间，但它的"存在"本身就是一种负担。

*这就是"遗忘"的代价。*

林小源想起了 init 童子。init 进程是所有孤儿进程的收养者——当一个进程的父进程先退出时，init 会成为这个进程的新父进程，并负责回收它的僵尸状态。init 童子的工作之一，就是不停地调用 `wait()` 来回收僵尸进程。

*原来 init 童子不只是"天选之子"，他还是"灵魂的回收者"。*

---

## 三

林小源在研究 `do_exit()` 的过程中，注意到了一个有趣的设计。

`do_exit()` 不是直接销毁 `task_struct`——它把 `task_struct` 留在系统中，变成僵尸。这是为了让父进程能够获取子进程的退出状态（`exit_code`）。

`waitpid(pid, &status, 0)` 会阻塞父进程，直到指定的子进程退出。当子进程退出后，`waitpid()` 返回子进程的 PID，并把退出状态写入 `status`。然后内核释放子进程的 `task_struct` 和 PID。

*原来 wait 是死亡仪式的最后一步。*

没有 `wait()`，子进程的死亡就不完整。它死了，但它的灵魂（`task_struct`）还在系统中游荡——这就是僵尸。

### 道藏笔记

::: tip 内核启示
**`do_exit()` 是进程退出的核心函数。**

它的核心路径：
1. 设置 `PF_EXITING` 标志，防止重复退出
2. `exit_mm()` — 释放地址空间（mm_struct）
3. `exit_files()` — 关闭所有文件描述符
4. `exit_fs()` — 释放文件系统信息
5. `exit_signal()` — 处理未决信号
6. `exit_notify()` — 通知父进程（发送 SIGCHLD）
7. 设置 `exit_state = EXIT_ZOMBIE`
8. `schedule()` — 切换到其他进程，永不返回

进程退出后变成僵尸，等待父进程调用 `wait()` 回收。`wait()` 会获取子进程的退出状态，然后释放 `task_struct` 和 PID。

如果父进程先退出，子进程会被 init（PID 1）收养。init 负责回收所有孤儿进程的僵尸状态。

*死亡不是终点。遗忘才是——当没有人 wait() 时，僵尸就永远游荡。*
:::
