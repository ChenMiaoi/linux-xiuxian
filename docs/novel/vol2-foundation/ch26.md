# 第二十六章：不可阻挡

<CultivationRealm realm="筑基中期" />

> **涉及内核源码：** <KernelSourceLink path="kernel/signal.c" line="sig_task_ignored" />

## 一

林小源在研究信号的过程中，撞上了一堵墙。

那堵墙叫 `SIGKILL`。

他看到一段代码——某个用户态程序试图用 `sigaction()` 注册 `SIGKILL` 的处理器。结果？`sigaction()` 返回 `-EINVAL`，注册失败。处理器根本没有被设置。

```c:playground:SIGKILL — 不可阻挡
#include <stdio.h>

/*
 * SIGKILL 和 SIGSTOP 的特殊性：
 * 1. 不能被信号处理器捕获
 * 2. 不能被信号掩码阻塞
 * 3. 不能被忽略
 *
 * 内核在 sig_task_ignored() 中检查：
 * 如果信号是 SIGKILL 或 SIGSTOP，直接返回 false
 * 意味着信号永远不会被"忽略"——必须执行默认行为
 */

#define SIGKILL  9
#define SIGSTOP 19
#define SIGTERM 15

struct sigaction {
    void (*handler)(int);
    unsigned long flags;
    unsigned long mask;
};

int do_sigaction(int sig, struct sigaction *act) {
    /* SIGKILL 和 SIGSTOP 不能被捕获 */
    if (sig == SIGKILL || sig == SIGSTOP) {
        return -1;  /* -EINVAL */
    }
    return 0;
}

int main() {
    struct sigaction act = { .handler = (void *)1, .flags = 0, .mask = 0 };

    printf("=== SIGKILL 的不可阻挡性 ===\n\n");

    int signals[] = { SIGTERM, SIGKILL, SIGSTOP };
    const char *names[] = { "SIGTERM", "SIGKILL", "SIGSTOP" };

    for (int i = 0; i < 3; i++) {
        int ret = do_sigaction(signals[i], &act);
        printf("sigaction(%s): %s\n", names[i],
               ret == 0 ? "注册成功" : "拒绝（EINVAL）");
    }

    printf("\n--- 为什么不可阻挡？ ---\n");
    printf("SIGKILL:  给管理员一个\"绝对\"的终止手段\n");
    printf("           如果进程能捕获 SIGKILL，恶意程序可以永远不死\n");
    printf("SIGSTOP:  给管理员一个\"绝对\"的暂停手段\n");
    printf("           如果进程能捕获 SIGSTOP，它可以拒绝被调试\n");

    printf("\n--- 内核实现 ---\n");
    printf("sig_task_ignored():\n");
    printf("  if (sig == SIGKILL || sig == SIGSTOP)\n");
    printf("      return false;  // 不可忽略\n");
    printf("\n");
    printf("SIG_KERNEL_ONLY_MASK:\n");
    printf("  #define SIG_KERNEL_ONLY_MASK (sigmask(SIGKILL) | sigmask(SIGSTOP))\n");
    printf("  任何对这个掩码的操作都被内核拒绝\n");

    return 0;
}
```

*有些力量，不是你不想面对就能逃避的。*

`SIGKILL` 是内核给管理员的"死刑执行令"。无论进程在做什么，无论它注册了什么处理器，`SIGKILL` 都能杀死它。这不是霸道——这是最后的保障。如果进程能捕获 `SIGKILL`，一个恶意程序就可以无限期地拒绝退出。

`SIGSTOP` 是"暂停执行令"。同样不可捕获。这保证了调试器（`ptrace`）可以暂停任何进程——如果进程能捕获 `SIGSTOP`，它就可以拒绝被调试。

*绝对的权力，为了绝对的秩序。*

## 二

林小源在研究 `SIGKILL` 的内核实现时，发现了一个例外。

PID 1。

`SIGKILL` 对 init 童子无效。

这是一条硬编码的规则。在 `sig_task_ignored()` 中，如果目标进程是 init（PID 1），`SIGKILL` 会被忽略。林小源找到这段代码时，愣了很久。

```c:playground:PID 1 的金身
#include <stdio.h>

/*
 * SIGKILL 对 PID 1 的特殊处理：
 * 在 sig_task_ignored() 中：
 *   if (is_global_init(tsk))  // PID 1
 *       return true;           // 忽略 SIGKILL
 *
 * 这保证了 init 进程永远不会被杀死。
 * 如果 init 死了，整个用户态世界崩溃。
 */

#define SIGKILL 9

struct task_struct {
    int pid;
    char comm[16];
    int is_init;
};

int sig_task_ignored(struct task_struct *tsk, int sig) {
    /* PID 1 对 SIGKILL 免疫 */
    if (tsk->is_init && sig == SIGKILL) {
        return 1;  /* 忽略 */
    }
    return 0;
}

int main() {
    struct task_struct procs[] = {
        { .pid = 1,    .comm = "init",    .is_init = 1 },
        { .pid = 100,  .comm = "shell",   .is_init = 0 },
        { .pid = 200,  .comm = "worker",  .is_init = 0 },
    };

    printf("=== SIGKILL 对不同进程的效果 ===\n\n");

    for (int i = 0; i < 3; i++) {
        int ignored = sig_task_ignored(&procs[i], SIGKILL);
        printf("SIGKILL → PID %d (%s): %s\n",
               procs[i].pid, procs[i].comm,
               ignored ? "被忽略（金身护体）" : "执行默认行为（终止）");
    }

    printf("\n--- 为什么 PID 1 有金身？ ---\n");
    printf("init 是所有孤儿进程的父进程\n");
    printf("init 负责回收僵尸进程\n");
    printf("init 管理系统服务的启动和停止\n");
    printf("如果 init 死了：\n");
    printf("  - 孤儿进程无人收养\n");
    printf("  - 僵尸进程堆积\n");
    printf("  - 系统服务无法管理\n");
    printf("  - 整个用户态世界崩溃\n");

    return 0;
}
```

*原来"天选之子"的金身，是用责任铸就的。*

林小源想起了 init 童子。那个曾经嘲笑他的存在，此刻在他眼中有了不同的含义。PID 1 不是特权——是枷锁。init 童子不能被杀死，不能退出，不能崩溃。他必须永远运行。

*他的傲慢，也许只是孤独的伪装。*

## 三

林小源在研究信号的过程中，还注意到了一个细节：`SIGKILL` 的默认行为是"Term"，但实际的终止过程比想象中复杂。

当内核处理 `SIGKILL` 时，它不会直接调用 `do_exit()`——它设置一个标志（`TIF_SIGPENDING`），然后在进程返回用户态时检查这个标志。如果标志被设置，内核调用 `do_group_exit()`，终止整个线程组。

*原来 SIGKILL 也是"延迟处理"的。*

这让林小源理解了内核设计的一个原则：**不在中断上下文中做复杂操作**。即使是 `SIGKILL`，也要等到进程返回用户态时才真正执行终止。因为终止过程需要释放资源、通知父进程——这些操作不能在中断上下文中完成。

*连"死刑"都有程序。*

### 道藏笔记

::: tip 内核启示
**`SIGKILL` 和 `SIGSTOP` 是内核中唯一不可被捕获、阻塞或忽略的信号。**

它们的特殊性由内核硬编码保证：
- `sigaction()` 对 `SIGKILL`/`SIGSTOP` 返回 `-EINVAL`
- `SIG_KERNEL_ONLY_MASK` 定义了这两个信号的掩码，任何对这个掩码的操作都被拒绝
- `sig_task_ignored()` 对 `SIGKILL`/`SIGSTOP` 直接返回 `false`

PID 1 的特殊保护：
- `is_global_init()` 检查目标进程是否是 init
- 如果是，`SIGKILL` 被忽略
- 这保证了 init 进程永远不会被杀死

`SIGKILL` 的处理流程：
1. `send_signal()` 设置 `TIF_SIGPENDING` 标志
2. 进程返回用户态时检查标志
3. 调用 `do_group_exit()` 终止整个线程组
4. `do_exit()` 释放资源，变成僵尸

*绝对的权力，是为了绝对的秩序。*
:::
