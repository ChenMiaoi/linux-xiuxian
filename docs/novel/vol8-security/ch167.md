# 第一百六十七章：内核地址空间布局

<CultivationRealm realm="渡劫期" />

> **涉及内核源码：** <KernelSourceLink path="arch/x86/mm/dump_pagetables.c" />

## 一

林小源在安全修炼中，发现了一个关键的防御机制——KASLR。

KASLR (Kernel Address Space Layout Randomization) 让内核在内存中的位置随机化。攻击者不知道内核在哪里，就无法可靠地利用漏洞。

```c:playground:KASLR — 隐藏内核位置
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

/*
 * KASLR (Kernel Address Space Layout Randomization):
 *
 * 作用:
 *   随机化内核在内存中的位置
 *   每次启动地址不同
 *   攻击者无法预测目标地址
 *
 * 随机化的对象:
 *   内核代码 (.text)
 *   内核数据 (.data)
 *   模块加载地址
 *   内核栈地址
 *
 * 绕过方法:
 *   信息泄漏 — 泄漏内核地址
 *   侧信道 — 利用缓存时序
 *   暴力破解 — 多次尝试
 *
 * 防御:
 *   KASLR — 随机化地址
 *   SMEP — 禁止执行用户空间代码
 *   SMAP — 禁止访问用户空间数据
 *   PAN — 禁止直接访问用户空间
 */

/* 模拟内核地址空间布局 */
struct kernel_layout {
    unsigned long kernel_base;
    unsigned long text_start;
    unsigned long text_end;
    unsigned long data_start;
    unsigned long data_end;
    unsigned long module_start;
    unsigned long module_end;
};

/* 模拟 KASLR 偏移 */
unsigned long kaslr_offset(void) {
    return (rand() % 0x1000) * 0x100000;
}

void print_layout(struct kernel_layout *l) {
    printf("  内核基址:   0x%lx\n", l->kernel_base);
    printf("  .text:      0x%lx - 0x%lx\n", l->text_start, l->text_end);
    printf("  .data:      0x%lx - 0x%lx\n", l->data_start, l->data_end);
    printf("  模块:       0x%lx - 0x%lx\n", l->module_start, l->module_end);
}

int main() {
    printf("=== KASLR — 隐藏内核位置 ===\n\n");

    srand(time(NULL));

    /* 没有 KASLR 的布局 */
    printf("--- 没有 KASLR ---\n");
    struct kernel_layout no_kaslr = {
        .kernel_base = 0xffffffff81000000,
        .text_start = 0xffffffff81000000,
        .text_end = 0xffffffff81800000,
        .data_start = 0xffffffff81800000,
        .data_end = 0xffffffff81c00000,
        .module_start = 0xffffffff81c00000,
        .module_end = 0xffffffff82000000,
    };
    print_layout(&no_kaslr);
    printf("  地址固定，攻击者知道目标\n\n");

    /* 有 KASLR 的布局 */
    printf("--- 有 KASLR ---\n");
    for (int i = 0; i < 3; i++) {
        printf("启动 %d:\n", i + 1);
        unsigned long offset = kaslr_offset();
        struct kernel_layout kaslr = {
            .kernel_base = 0xffffffff81000000 + offset,
            .text_start = 0xffffffff81000000 + offset,
            .text_end = 0xffffffff81800000 + offset,
            .data_start = 0xffffffff81800000 + offset,
            .data_end = 0xffffffff81c00000 + offset,
            .module_start = 0xffffffff81c00000 + offset,
            .module_end = 0xffffffff82000000 + offset,
        };
        print_layout(&kaslr);
        printf("  偏移: 0x%lx\n\n", offset);
    }

    printf("--- 防御机制 ---\n");
    printf("KASLR:\n");
    printf("  随机化内核地址\n");
    printf("  每次启动不同\n\n");
    printf("SMEP:\n");
    printf("  禁止执行用户空间代码\n");
    printf("  防止跳转到用户空间\n\n");
    printf("SMAP:\n");
    printf("  禁止访问用户空间数据\n");
    printf("  防止读写用户空间\n\n");

    printf("--- 绕过方法 ---\n");
    printf("1. 信息泄漏:\n");
    printf("   泄漏内核地址\n");
    printf("   /proc/kallsyms\n\n");
    printf("2. 侧信道:\n");
    printf("   缓存时序攻击\n\n");
    printf("3. 暴力破解:\n");
    printf("   多次尝试\n");
    printf("   256 种可能\n");

    return 0;
}
```

*原来"KASLR"是"隐藏"的"屏障"。*

---

## 二

林小源在研究 KASLR 的过程中，理解了随机化的原理。

KASLR 在启动时随机选择内核加载地址。每次启动地址都不同。攻击者无法预测内核函数的地址，就无法可靠地跳转到恶意代码。

*原来"随机化"是"安全"的"基石"。*

---

## 三

林小源在观察 KASLR 的过程中，理解了它的局限性。

KASLR 可以被信息泄漏绕过。如果攻击者能读取 /proc/kallsyms 或泄漏内核指针，就能计算出 KASLR 偏移。所以需要多层防御。

*原来"单层防御"是"不够"的。*
