# 第一百一十七章：拥塞

<CultivationRealm realm="问道期" />

> **涉及内核源码：** <KernelSourceLink path="net/ipv4/tcp_cong.c" />

## 一

林小源在研究 TCP 的过程中，发现了一个关键问题：网络会拥塞。

当太多数据包同时涌向网络时，路由器的缓冲区会溢出，数据包会被丢弃。TCP 的拥塞控制机制通过调整发送速率来避免网络过载。

```c:playground:TCP 拥塞控制 — 避免网络过载
#include <stdio.h>

/*
 * 拥塞控制的核心算法：
 *
 * 1. 慢启动 (Slow Start)
 *    cwnd 从 1 MSS 开始
 *    每收到一个 ACK，cwnd++
 *    cwnd 指数增长
 *
 * 2. 拥塞避免 (Congestion Avoidance)
 *    cwnd 达到 ssthresh 后
 *    cwnd 线性增长
 *
 * 3. 快重传 (Fast Retransmit)
 *    收到 3 个重复 ACK
 *    立即重传丢失的包
 *
 * 4. 快恢复 (Fast Recovery)
 *    ssthresh = cwnd / 2
 *    cwnd = ssthresh
 *    进入拥塞避免
 *
 * 拥塞检测：
 *   超时: cwnd = 1, 慢启动
 *   重复 ACK: 快重传 + 快恢复
 */

int main() {
    printf("=== TCP 拥塞控制 — 避免网络过载 ===\n\n");

    printf("拥塞控制的核心算法:\n\n");

    printf("1. 慢启动:\n");
    printf("   cwnd = 1 MSS\n");
    printf("   每个 ACK: cwnd++\n");
    printf("   cwnd: 1 → 2 → 4 → 8 → 16...\n\n");

    printf("2. 拥塞避免:\n");
    printf("   cwnd >= ssthresh\n");
    printf("   每个 RTT: cwnd++\n");
    printf("   cwnd 线性增长\n\n");

    printf("3. 快重传:\n");
    printf("   收到 3 个重复 ACK\n");
    printf("   立即重传\n\n");

    printf("4. 快恢复:\n");
    printf("   ssthresh = cwnd / 2\n");
    printf("   cwnd = ssthresh\n");
    printf("   进入拥塞避免\n\n");

    printf("--- 拥塞窗口变化 ---\n");
    printf("cwnd\n");
    printf("  │    /\\      拥塞\n");
    printf("  │   /  \\     ↓\n");
    printf("  │  /    \\   快恢复\n");
    printf("  │ /      \\  /\n");
    printf("  │/ 慢启动 \\/\n");
    printf("  └──────────── time\n\n");

    printf("--- 拥塞算法 ---\n");
    printf("Reno:\n");
    printf("  经典算法\n");
    printf("  快重传 + 快恢复\n\n");
    printf("CUBIC:\n");
    printf("  默认算法\n");
    printf("  三次函数增长\n\n");
    printf("BBR:\n");
    printf("  Google 提出\n");
    printf("  基于带宽和延迟\n");

    return 0;
}
```

*原来"慢"是为了"更快"。*

---

## 二

林小源在研究拥塞控制的过程中，理解了慢启动的智慧。

TCP 不是一开始就全速发送——它从慢开始，指数增长。当检测到拥塞时，回到慢启动。这种"探测"机制让 TCP 能够适应不同的网络条件。

*原来"探测"是"适应"的方式。*

---

## 三

林小源在观察拥塞控制的过程中，理解了 BBR 的创新。

传统拥塞控制基于丢包检测拥塞——但丢包不一定意味着拥塞（可能是无线干扰）。BBR 基于带宽和延迟来判断网络状态，更准确地控制发送速率。

*原来"信号"可以"误导"。*

### 道藏笔记

::: tip 内核启示
**TCP 拥塞控制避免网络过载。**

拥塞控制算法：
- 慢启动 — cwnd 指数增长
- 拥塞避免 — cwnd 线性增长
- 快重传 — 收到 3 个重复 ACK 立即重传
- 快恢复 — cwnd 减半后进入拥塞避免

拥塞算法：
- Reno — 经典算法
- CUBIC — 默认算法，三次函数增长
- BBR — 基于带宽和延迟

*拥塞控制是"探测"——让 TCP 适应网络条件。*
:::
