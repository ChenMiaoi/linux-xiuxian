# 第一百零四章：隔海有界

<CultivationRealm realm="问道期" />

> **涉及内核源码：** <KernelSourceLink path="include/net/net_namespace.h" line="struct net" />

## 一

林小源以为网络之海只有一片，直到他看见海面被无形的墙分开。

墙内有自己的 loopback 岛、自己的路由潮汐、自己的 netfilter 礁阵、自己的端口名册。墙外的船影明明近在眼前，却像活在另一幅海图里。

"这是网络命名空间。"海关小吏说，"第二卷你见过 namespace 的幻境，但那时只是远远看了一眼。网络卷里，它会变成真正的海界。"

林小源走到墙边，看到墙上刻着 `struct net`。其中有 `loopback_dev`，也有 IPv4、IPv6、packet、unix、netfilter、nftables、bpf 等分区。

"所以 `struct net` 不是一个标签。"

"不是。"小吏说，"它是一片网络世界的根。"

## 二

小吏带他登上一座高台。

台下有两片看似相同的海。两边都有 `lo`，都有 `127.0.0.1`，都有进程在监听 `8080` 端口。林小源本能地以为它们会冲突，可两边钟声各响各的，没有任何碰撞。

"同一个地址，在不同 netns 里可以各自成立。"小吏说，"因为端口、路由、设备、协议状态都挂在各自的网络世界里。容器能拥有自己的网络视角，靠的不是换一套 TCP，而是给它一片独立的 `struct net`。"

"那它们怎么连接外界？"

"靠虚拟设备、veth、bridge、路由、NAT。"小吏指向远处几座尚未开启的码头，"那些是后面的章节。现在你只需要知道：隔离不是断绝，隔离是边界清晰之后再安排通路。"

## 三

林小源想起第三十二章的 cgroup。

"cgroup 管资源，namespace 管视角。"他说，"网络命名空间让进程看到不同的网络世界，但不直接限制它能用多少 CPU 或内存。"

小吏点头："这句话要记牢。很多人把容器说成一个法术，其实它是多种机制叠起来的。mount namespace 改文件系统视角，PID namespace 改进程编号视角，net namespace 改网络视角，cgroup 管资源压力。混在一起写，就会把天道写乱。"

海墙上的符文渐渐隐去，变成一张等待展开的海图。

林小源知道，第一百二十三章他还会回到这里。那时他看到的将不只是墙，而是墙上的门、桥和防火阵。

### 道藏笔记

::: tip 内核启示
网络命名空间让一组进程拥有独立网络视角。内核中 `struct net` 承载一片网络世界的状态，包括 loopback 设备、协议栈状态、netfilter/nftables、BPF 等子系统资源。

namespace 和 cgroup 边界不同：namespace 改变进程看到的对象集合，cgroup 约束和统计资源。网络命名空间是后续 netfilter、虚拟设备、容器网络和 Netlink 配置的共同背景。
:::
