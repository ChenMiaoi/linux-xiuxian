# 第一百零二章：协议族名册

<CultivationRealm realm="问道期" />

> **涉及内核源码：** <KernelSourceLink path="net/socket.c" line="__sock_create" />

## 一

海关小吏没有马上放行。

他摊开一本厚厚的名册，第一页写着 `AF_INET`，第二页写着 `AF_INET6`，第三页写着 `AF_UNIX`，再往后还有 `AF_NETLINK`、`AF_PACKET` 等陌生名字。每一页旁边都挂着不同颜色的船牌。

"这是什么？"林小源问。

"协议族名册。"小吏说，"你调用 `socket(family, type, protocol)`，第一句话就是报家门。`family` 决定你要进哪片水域，`type` 决定你要什么船型，`protocol` 决定更具体的航法。"

林小源翻到 `AF_INET` 一页，里面画着 IPv4 的海图；翻到 `AF_UNIX`，却是一片内湖；翻到 `AF_NETLINK`，看见用户态和内核之间有信号旗往返。

"所以 socket 不是一种东西。"他说。

"socket 是统一入口。"小吏合上名册，"真正的水域由协议族决定。"

## 二

小吏领着林小源走进一座登记厅。

厅内每个柜台背后都坐着一位协议族掌簿人。IPv4 掌簿人检查 `AF_INET`，Unix domain 掌簿人只处理本地内湖，Netlink 掌簿人则专门传递内核与用户态的配置消息。

"他们怎么被内核找到？"林小源问。

"协议族会注册自己的 create 方法。"小吏说，"通用 socket 层不需要知道每片海怎么造船，它只要根据 `family` 找到对应的 `net_proto_family`，再调用那一族的 `create`。造出来之后，socket 上会挂一套 `proto_ops`，以后 `bind()`、`connect()`、`accept()`、`sendmsg()`、`recvmsg()` 都按这套操作表分派。"

林小源立刻想起 VFS 的 `file_operations`。

"像文件系统的 operations？"

"正是。"小吏点头，"VFS 用 operations 统一 ext4、btrfs、procfs；socket 层用 `proto_ops` 统一 TCP、UDP、Unix domain、Netlink。统一入口背后，是不同门派各自实现。"

## 三

名册最后一页写着一行小字：同一个名字，在不同命名空间里可能指向不同海图。

林小源看了很久，才问："这是什么意思？"

小吏收起笑意："你现在只要记住，协议族不是孤立存在。它们常常还要依附网络命名空间。`AF_INET` 的路由表、设备、netfilter 规则，不一定在所有世界里相同。到了后面，你会看到同一台机器上可以有多片互相隔离的海。"

远处海雾中，一艘船影从 `AF_INET` 的码头驶出，又在另一片雾中消失。林小源忽然意识到，网络不只是协议，还包括协议所在的世界。

名册第一页给了他入口，最后一页却给了他疑问。

### 道藏笔记

::: tip 内核启示
`socket(family, type, protocol)` 的三元组决定 socket 创建路径。`family` 选择协议族，例如 `AF_INET`、`AF_INET6`、`AF_UNIX`、`AF_NETLINK`；`type` 选择通信语义，例如 stream、datagram、raw；`protocol` 进一步指定协议。

通用 socket 层根据协议族找到对应实现，创建后通过 `proto_ops` 分派 `bind()`、`connect()`、`listen()`、`accept()`、`sendmsg()`、`recvmsg()` 等操作。这和 VFS 通过 operations 统一不同文件系统是同一种内核设计味道。
:::
