# 第一百零三章：入海之门

<CultivationRealm realm="问道期" />

> **涉及内核源码：** <KernelSourceLink path="net/socket.c" line="__sys_socket" />

## 一

林小源终于站在了真正的入海门前。

门楣上刻着 `__sys_socket()`，门后却不是一条直路，而是三道关卡。第一关检查参数，第二关创建 socket，第三关把 socket 安装成 fd。每一道关卡都不大，却少一道都不能出海。

"用户态喊的是 `socket()`。"海关小吏说，"内核里会走到 `__sys_socket()`，再进入 `__sys_socket_create()` 和 `sock_create()`。`sock_create()` 不是凭空造船，它会把当前进程所在的网络命名空间带进去，然后调用更底层的 `__sock_create()`。"

林小源看到门内有一道影子从 `current->nsproxy->net_ns` 处落下，像一枚世界印章盖在申请书上。

"所以 socket 创建时，已经带上了它所在的网络世界。"

"对。"小吏说，"你还没看见海，海已经先决定了。"

## 二

第二关里，掌簿人把协议族名册摊开。

`__sock_create()` 根据 `family` 找到对应协议族，调用那一族的 `create`。如果协议族不存在，门会关闭；如果类型和协议组合不被支持，船也造不出来。

林小源看着一张空白船契逐渐成形。它先有了 `struct socket` 的外壳，又被协议族填入更具体的内核对象。TCP 会走向 `struct sock` 和 TCP 协议控制块，UDP 有自己的轻舟，Unix domain 则走向本地内湖的队列。

"通用层只负责秩序。"小吏说，"具体怎么造，由协议族负责。"

"那 `proto_ops` 呢？"

"造好后挂上。"小吏把一枚操作表钉到船契上，"以后同样叫 `connect()`，不同协议族会走不同实现。统一入口，分派执行。"

## 三

第三关最不起眼。

小吏把造好的 socket 装进一只 file 匣子，又把匣子塞进进程的 fd table。林小源这才拿到一个小小的整数。这个整数看起来轻得像一枚铜钱，背后却拴着协议族、操作表、网络命名空间和 socket 对象。

"这就是为什么错误处理很重要。"小吏说，"前面造船成功，后面安装 fd 失败，也要把 socket 放回去。内核里的每一步都要考虑引用和清理，否则海还没出，码头先漏水。"

林小源握紧那枚 fd，第一次觉得一个整数并不简单。

它是入海之门的通行符，也是文件系统、进程表、网络命名空间、协议族之间的交叉点。

### 道藏笔记

::: tip 内核启示
`socket()` 的用户态入口很简单，内核路径却分层清晰：系统调用进入 `__sys_socket()`，创建阶段走 `sock_create()` / `__sock_create()`，协议族负责具体创建，最后把 socket 映射为 fd。

关键边界是：通用 socket 层负责统一入口和对象生命周期，协议族负责具体语义，fd table 负责把内核对象暴露给进程。任何一步失败都要正确释放引用。
:::
