# 第六十六章：kswapd

<CultivationRealm realm="元婴中期" />

## 一

林小源在内存管理的世界中，遇到了 kswapd——内核的交换守护进程。

kswapd 是一个内核线程，负责在后台回收页面。当内存水位低于阈值时，kswapd 被唤醒，开始回收页面。

```c:playground:kswapd — 内存回收的守护者
#include <stdio.h>

/*
 * kswapd 的工作原理：
 *
 * 内存水位：
 *   high  — 内存充足
 *   low   — 内存紧张，唤醒 kswapd
 *   min   — 内存严重不足，直接回收
 *
 * kswapd 的工作流程：
 *   1. 等待内存水位低于 low
 *   2. 被唤醒
 *   3. 回收页面直到水位回到 high
 *   4. 继续等待
 *
 * 直接回收 (direct reclaim)：
 *   当内存严重不足时，进程自己回收页面
 *   不等待 kswapd
 *   可能导致进程阻塞
 */

enum watermarks {
    WMARK_MIN,
    WMARK_LOW,
    WMARK_HIGH,
};

struct zone {
    const char *name;
    int free_pages;
    int watermarks[3];
};

int should_wakeup(struct zone *z) {
    return z->free_pages <= z->watermarks[WMARK_LOW];
}

int reclaim_pages(struct zone *z, int nr) {
    z->free_pages += nr;
    return nr;
}

int main() {
    printf("=== kswapd — 内存回收的守护者 ===\n\n");

    struct zone z = {
        .name = "Normal",
        .free_pages = 50,
        .watermarks = { 20, 50, 100 },  /* min, low, high */
    };

    printf("内存水位：\n");
    printf("  high: %d 页\n", z.watermarks[WMARK_HIGH]);
    printf("  low:  %d 页\n", z.watermarks[WMARK_LOW]);
    printf("  min:  %d 页\n", z.watermarks[WMARK_MIN]);
    printf("  当前: %d 页\n\n", z.free_pages);

    /* 模拟内存压力 */
    printf("--- 内存压力增加 ---\n");
    z.free_pages = 45;
    printf("  当前: %d 页\n", z.free_pages);
    printf("  低于 low 阈值? %s\n\n",
           should_wakeup(&z) ? "是 → 唤醒 kswapd" : "否");

    /* kswapd 回收页面 */
    if (should_wakeup(&z)) {
        printf("[kswapd] 被唤醒，开始回收页面\n");
        int reclaimed = reclaim_pages(&z, 30);
        printf("[kswapd] 回收了 %d 页\n", reclaimed);
        printf("[kswapd] 当前: %d 页\n", z.free_pages);
        printf("[kswapd] 达到 high 阈值? %s\n\n",
               z.free_pages >= z.watermarks[WMARK_HIGH] ? "是 → 继续等待" : "否 → 继续回收");
    }

    /* 直接回收 */
    printf("--- 直接回收 ---\n");
    z.free_pages = 15;
    printf("  当前: %d 页\n", z.free_pages);
    printf("  低于 min 阈值? %s\n",
           z.free_pages <= z.watermarks[WMARK_MIN] ? "是 → 直接回收" : "否");
    if (z.free_pages <= z.watermarks[WMARK_MIN]) {
        printf("  [direct reclaim] 进程自己回收页面\n");
        printf("  可能导致进程阻塞\n");
    }

    printf("\n--- kswapd vs 直接回收 ---\n");
    printf("kswapd:\n");
    printf("  - 后台运行，不阻塞进程\n");
    printf("  - 在内存水位低于 low 时唤醒\n");
    printf("  - 回收到 high 水位后继续等待\n\n");
    printf("直接回收:\n");
    printf("  - 前台运行，阻塞进程\n");
    printf("  - 在内存水位低于 min 时触发\n");
    printf("  - 紧急情况下的回收\n");

    return 0;
}
```

*原来 kswapd 是内存的"守护者"——在后台默默回收页面。*

## 二

林小源在研究 kswapd 的过程中，理解了内存水位的概念。

内存水位有三个阈值：`high`、`low`、`min`。当空闲页面低于 `low` 时，唤醒 kswapd；当空闲页面低于 `min` 时，触发直接回收。

*原来"水位"是内存压力的"度量"。*

---

## 三

林小源在观察 kswapd 的过程中，理解了后台回收和前台回收的区别。

kswapd 是后台回收——它在后台运行，不阻塞进程。直接回收是前台回收——它在进程的上下文中运行，可能导致进程阻塞。

*原来"后台"和"前台"有不同的"代价"。*
