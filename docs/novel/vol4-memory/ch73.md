# 第七十三章：NUMA

<CultivationRealm realm="元婴后期" />

> **涉及内核源码：** <KernelSourceLink path="mm/mempolicy.c" line="do_set_mempolicy" />

## 一

林小源在研究多处理器系统的过程中，发现了一个新的问题：内存访问并不总是等价的。

在 NUMA（Non-Uniform Memory Access）架构中，每个 CPU 都有自己"本地"的内存。访问本地内存很快，访问"远程"内存（其他 CPU 的内存）则慢得多。

```c:playground:NUMA — 非一致内存访问
#include <stdio.h>

/*
 * NUMA 架构：
 *
 *   Node 0          Node 1
 *   ┌─────┐         ┌─────┐
 *   │ CPU │         │ CPU │
 *   │ 0,1 │         │ 2,3 │
 *   └──┬──┘         └──┬──┘
 *      │               │
 *   ┌──┴──┐         ┌──┴──┐
 *   │ 本地 │         │ 本地 │
 *   │ 内存 │         │ 内存 │
 *   └─────┘         └─────┘
 *
 * 访问延迟：
 *   本地内存: ~100ns
 *   远程内存: ~150-300ns
 *
 * 内存策略：
 *   MPOL_DEFAULT   — 在当前节点分配
 *   MPOL_BIND      — 只在指定节点分配
 *   MPOL_INTERLEAVE — 在多个节点间轮转分配
 *   MPOL_PREFERRED  — 优先在指定节点分配
 */

int main() {
    printf("=== NUMA — 非一致内存访问 ===\n\n");

    printf("NUMA vs UMA:\n");
    printf("  UMA (统一内存访问):\n");
    printf("    所有 CPU 访问同一内存\n");
    printf("    访问延迟相同\n");
    printf("    适合小规模系统\n\n");
    printf("  NUMA (非一致内存访问):\n");
    printf("    每个 CPU 有本地内存\n");
    printf("    本地访问快，远程访问慢\n");
    printf("    适合大规模系统\n\n");

    printf("--- NUMA 节点示例 ---\n");
    printf("Node 0: CPU 0-3, 内存 0-16GB\n");
    printf("  本地访问: ~100ns\n");
    printf("Node 1: CPU 4-7, 内存 16-32GB\n");
    printf("  本地访问: ~100ns\n");
    printf("  远程访问: ~200ns\n\n");

    printf("--- 内存策略 ---\n");
    printf("MPOL_DEFAULT:\n");
    printf("  在当前节点分配\n");
    printf("  最简单的策略\n\n");
    printf("MPOL_BIND:\n");
    printf("  只在指定节点分配\n");
    printf("  如果内存不足，不回退到其他节点\n\n");
    printf("MPOL_INTERLEAVE:\n");
    printf("  在多个节点间轮转分配\n");
    printf("  适合大块内存，分散带宽压力\n\n");
    printf("MPOL_PREFERRED:\n");
    printf("  优先在指定节点分配\n");
    printf("  如果内存不足，回退到其他节点\n\n");

    printf("--- set_mempolicy 系统调用 ---\n");
    printf("set_mempolicy(MPOL_BIND, &nodemask, maxnode);\n");
    printf("  设置当前进程的内存策略\n\n");
    printf("mbind(addr, len, MPOL_INTERLEAVE, ...);\n");
    printf("  设置特定内存区域的策略\n");

    return 0;
}
```

*原来"近"和"远"在内存中也是相对的。*

---

## 二

林小源在研究 NUMA 的过程中，理解了内存策略的重要性。

默认策略是在当前节点分配内存——但如果进程在不同节点间迁移，可能会导致大量远程访问。显式设置内存策略可以优化性能。

*原来"策略"决定了"在哪里"分配内存。*

---

## 三

林小源在观察 NUMA 的过程中，理解了自动 NUMA 平衡的机制。

Linux 内核有自动 NUMA 平衡功能——它可以检测进程频繁访问的远程内存，并自动将页面迁移到本地节点。这个过程对应用程序透明。

*原来内核也会"自动优化"。*

---

### 道藏笔记

::: tip 内核启示
**NUMA 架构中，内存访问延迟取决于位置。**

NUMA 的特点：
- 每个 CPU 有本地内存
- 本地访问快，远程访问慢
- 适合大规模多处理器系统

内存策略：
- `MPOL_DEFAULT` — 在当前节点分配
- `MPOL_BIND` — 只在指定节点分配
- `MPOL_INTERLEAVE` — 在多个节点间轮转分配
- `MPOL_PREFERRED` — 优先在指定节点分配

自动 NUMA 平衡：
- 内核检测远程内存访问
- 自动迁移页面到本地节点
- 对应用程序透明

*NUMA 让"距离"成为性能的关键因素。*
:::
