# 第五十七章：页表经脉

<CultivationRealm realm="元婴初期" />

> **涉及内核源码：** <KernelSourceLink path="arch/riscv/include/asm/pgtable.h" line="pte_val" />

## 一

林小源在内存管理的世界中，发现了一套精密的"经脉系统"——页表。

页表是虚拟地址到物理地址的映射表。在 RISC-V 64 位系统中，使用 Sv39 页表格式——三级页表，每级 9 位索引。

```c:playground:Sv39 页表 — 地址翻译的经脉
#include <stdio.h>

/*
 * Sv39 页表结构（RISC-V 64 位）：
 *
 * 虚拟地址 (39 位有效):
 *   [38:30] — VPN[2] (L2 索引，9 位)
 *   [29:21] — VPN[1] (L1 索引，9 位)
 *   [20:12] — VPN[0] (L0 索引，9 位)
 *   [11:0]  — 页内偏移 (12 位)
 *
 * 页表项 (PTE) 格式:
 *   [63:54] — 保留
 *   [53:28] — PPN[2] (物理页号高 26 位)
 *   [27:19] — PPN[1] (物理页号中 9 位)
 *   [18:10] — PPN[0] (物理页号低 9 位)
 *   [9:0]   — 标志位
 *
 * 标志位:
 *   V — Valid (有效)
 *   R — Read (可读)
 *   W — Write (可写)
 *   X — Execute (可执行)
 *   U — User (用户态可访问)
 *   G — Global (全局)
 *   A — Accessed (已访问)
 *   D — Dirty (已修改)
 */

#define PTE_V (1 << 0)
#define PTE_R (1 << 1)
#define PTE_W (1 << 2)
#define PTE_X (1 << 3)
#define PTE_U (1 << 4)
#define PTE_A (1 << 6)
#define PTE_D (1 << 7)

int main() {
    printf("=== Sv39 页表 — 地址翻译的经脉 ===\n\n");

    /* 虚拟地址示例 */
    unsigned long va = 0x0000003FCA123456;

    printf("虚拟地址: 0x%016lx\n\n", va);

    /* 提取 VPN */
    unsigned long vpn2 = (va >> 30) & 0x1FF;
    unsigned long vpn1 = (va >> 21) & 0x1FF;
    unsigned long vpn0 = (va >> 12) & 0x1FF;
    unsigned long offset = va & 0xFFF;

    printf("VPN[2] (L2 索引): %lu (0x%03lx)\n", vpn2, vpn2);
    printf("VPN[1] (L1 索引): %lu (0x%03lx)\n", vpn1, vpn1);
    printf("VPN[0] (L0 索引): %lu (0x%03lx)\n", vpn0, vpn0);
    printf("页内偏移:         %lu (0x%03lx)\n\n", offset, offset);

    /* 页表项示例 */
    unsigned long pte = 0x200000CF;  /* PPN + flags */
    printf("PTE: 0x%016lx\n", pte);
    printf("  PPN: 0x%09lx\n", (pte >> 10) & 0xFFFFFFFFF);
    printf("  V=%lu R=%lu W=%lu X=%lu U=%lu A=%lu D=%lu\n",
           (pte >> 0) & 1, (pte >> 1) & 1, (pte >> 2) & 1,
           (pte >> 3) & 1, (pte >> 4) & 1, (pte >> 6) & 1,
           (pte >> 7) & 1);

    printf("\n--- 页表翻译过程 ---\n");
    printf("1. 读取 satp 寄存器，获取根页表地址\n");
    printf("2. 用 VPN[2] 索引 L2 页表，获取 L1 页表地址\n");
    printf("3. 用 VPN[1] 索引 L1 页表，获取 L0 页表地址\n");
    printf("4. 用 VPN[0] 索引 L0 页表，获取物理页号\n");
    printf("5. 物理地址 = PPN << 12 | offset\n");

    printf("\n--- 页大小 ---\n");
    printf("4KB 页:  三级页表\n");
    printf("2MB 大页: 二级页表（跳过 L0）\n");
    printf("1GB 大页: 一级页表（跳过 L0 和 L1）\n");

    return 0;
}
```

*原来地址翻译是一套精密的"经脉"系统。*

## 二

林小源在研究页表的过程中，理解了 PTE（页表项）的每一个 bit。

PTE 不仅包含物理页号，还包含一组标志位：`V`（有效）、`R`（可读）、`W`（可写）、`X`（可执行）、`U`（用户态可访问）、`A`（已访问）、`D`（已修改）。

*原来页表项是"权限"和"地址"的组合。*

林小源还发现了一个有趣的设计：`A`（Accessed）和 `D`（Dirty）位由硬件设置。当页面被访问时，硬件自动设置 `A` 位；当页面被写入时，硬件自动设置 `D` 位。内核通过检查这些位来判断页面是否被使用——这是页面回收的基础。

*原来"硬件"和"内核"是"协作"的。*

---

## 三

林小源在观察页表的过程中，理解了 TLB（Translation Lookaside Buffer）的作用。

页表翻译需要三次内存访问（三级页表）——这太慢了。TLB 是页表的缓存，存储最近使用的虚拟地址到物理地址的映射。有了 TLB，地址翻译可以在一个时钟周期内完成。

*原来"缓存"是"加速"的关键。*

### 道藏笔记

::: tip 内核启示
**Sv39 页表是 RISC-V 64 位系统的地址翻译机制。**

虚拟地址结构（39 位有效）：
- `VPN[2]` — L2 索引（9 位）
- `VPN[1]` — L1 索引（9 位）
- `VPN[0]` — L0 索引（9 位）
- 页内偏移 — 12 位

PTE（页表项）标志位：
- `V` — Valid（有效）
- `R` — Read（可读）
- `W` — Write（可写）
- `X` — Execute（可执行）
- `U` — User（用户态可访问）
- `A` — Accessed（已访问，硬件设置）
- `D` — Dirty（已修改，硬件设置）

页大小：
- 4KB 页 — 三级页表
- 2MB 大页 — 二级页表
- 1GB 大页 — 一级页表

TLB 是页表的缓存——地址翻译的"加速器"。

*页表是内存管理的"经脉"——虚拟与物理的桥梁。*
:::
