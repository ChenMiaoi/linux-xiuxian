# 第七十七章：透明大页

<CultivationRealm realm="元婴后期" />

> **涉及内核源码：** <KernelSourceLink path="mm/khugepaged.c" line="khugepaged" />

## 一

林小源在研究大页的过程中，发现了一个问题：传统大页需要应用程序显式使用——要么通过 `hugetlbfs`，要么通过 `MAP_HUGETLB` 标志。这对应用程序不透明。

透明大页（Transparent Huge Pages, THP）解决了这个问题。它让内核自动使用大页，应用程序不需要任何修改。

```c:playground:透明大页 — 自动的大页优化
#include <stdio.h>

/*
 * 透明大页 (THP) 的工作原理：
 *
 * 1. 自动提升 (Promotion)
 *    内核检测到连续的小页
 *    自动合并成大页
 *
 * 2. 自动降级 (Demotion)
 *    大页需要回收部分内存
 *    自动拆分成小页
 *
 * 3. khugepaged 守护进程
 *    后台扫描内存
 *    自动合并适合的大页
 *
 * THP 的模式：
 *   always  — 总是使用 THP
 *   madvise — 只对 madvise(MADV_HUGEPAGE) 的区域使用
 *   never   — 不使用 THP
 *
 * THP 的好处：
 *   - 不需要应用程序修改
 *   - 自动优化 TLB 性能
 *   - 减少页表项
 *
 * THP 的问题：
 *   - 延迟波动（合并/拆分开销）
 *   - 内存浪费（内部碎片）
 *   - 不适合所有工作负载
 */

int main() {
    printf("=== 透明大页 — 自动的大页优化 ===\n\n");

    printf("传统大页 vs 透明大页:\n");
    printf("  传统大页:\n");
    printf("    需要应用程序显式使用\n");
    printf("    hugetlbfs 或 MAP_HUGETLB\n");
    printf("    预先分配\n\n");
    printf("  透明大页:\n");
    printf("    自动使用，不需要修改\n");
    printf("    内核自动合并/拆分\n");
    printf("    按需分配\n\n");

    printf("--- THP 的工作流程 ---\n");
    printf("1. 进程分配内存\n");
    printf("   内核分配 4KB 小页\n\n");
    printf("2. khugepaged 扫描\n");
    printf("   检测连续的小页\n\n");
    printf("3. 自动提升\n");
    printf("   合并 512 个小页 → 1 个 2MB 大页\n\n");
    printf("4. 自动降级\n");
    printf("   需要回收时，拆分大页\n\n");

    printf("--- THP 模式 ---\n");
    printf("always:\n");
    printf("  总是使用 THP\n");
    printf("  适合大内存应用\n\n");
    printf("madvise:\n");
    printf("  只对明确标记的区域使用\n");
    printf("  madvise(addr, len, MADV_HUGEPAGE)\n\n");
    printf("never:\n");
    printf("  不使用 THP\n");
    printf("  避免延迟波动\n\n");

    printf("--- THP 的问题 ---\n");
    printf("1. 延迟波动\n");
    printf("   合并/拆分需要时间\n");
    printf("   可能导致延迟尖峰\n\n");
    printf("2. 内存浪费\n");
    printf("   内部碎片（不需要整个大页）\n\n");
    printf("3. 不适合所有工作负载\n");
    printf("   小内存应用可能更慢\n");

    return 0;
}
```

*原来"透明"意味着"不需要改变"。*

---

## 二

林小源在研究透明大页的过程中，理解了 `khugepaged` 的作用。

`khugepaged` 是内核的透明大页守护进程。它在后台运行，扫描内存，找到适合合并的小页，然后自动提升为大页。这个过程对应用程序完全透明。

*原来"后台优化"是自动的。*

---

## 三

林小源在观察透明大页的过程中，理解了它的争议。

透明大页并不是所有场景都适合。对于延迟敏感的应用（如数据库、交易系统），THP 的合并/拆分可能导致延迟波动。有些系统管理员选择禁用 THP。

*原来"自动"不一定"最优"。*

### 道藏笔记

::: tip 内核启示
**透明大页（THP）让内核自动使用大页。**

THP 的工作原理：
- 自动提升：合并连续小页为大页
- 自动降级：需要时拆分大页为小页
- `khugepaged` 后台扫描和合并

THP 的模式：
- `always` — 总是使用
- `madvise` — 只对标记区域使用
- `never` — 不使用

THP 的优势：
- 不需要应用程序修改
- 自动优化 TLB 性能

THP 的问题：
- 延迟波动
- 内存浪费
- 不适合所有工作负载

*THP 是"自动优化"——但自动不一定最优。*
:::
