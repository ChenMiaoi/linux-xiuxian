## 一

林小源在研究内存管理的过程中，发现了一个重要问题：如何找到内存相关的 bug？

内存 bug 很难调试——越界访问、使用已释放内存、未初始化内存，这些问题可能不会立即崩溃，而是在很久后才显现。

```c:playground:内存调试 — 找到隐藏的 bug
#include <stdio.h>

/*
 * 常见的内存 bug：
 *
 * 1. 越界访问 (Out-of-bounds)
 *    int arr[10];
 *    arr[10] = 42;  // 越界！
 *
 * 2. 使用已释放内存 (Use-after-free)
 *    ptr = malloc(size);
 *    free(ptr);
 *    *ptr = 42;  // 使用已释放内存！
 *
 * 3. 未初始化内存 (Uninitialized memory)
 *    int arr[10];
 *    printf("%d", arr[0]);  // 未初始化！
 *
 * 4. 双重释放 (Double free)
 *    free(ptr);
 *    free(ptr);  // 双重释放！
 *
 * 内核的调试工具：
 *   KASAN — 内核地址消毒器
 *   KMSAN — 内核内存消毒器
 *   KMEMLEAK — 内存泄漏检测
 *   DEBUG_PAGEALLOC — 页分配调试
 */

int main() {
    printf("=== 内存调试 — 找到隐藏的 bug ===\n\n");

    printf("常见的内存 bug:\n\n");

    printf("1. 越界访问 (Out-of-bounds)\n");
    printf("   int arr[10];\n");
    printf("   arr[10] = 42;  // 访问第 11 个元素\n");
    printf("   可能破坏相邻数据\n\n");

    printf("2. 使用已释放内存 (Use-after-free)\n");
    printf("   ptr = malloc(size);\n");
    printf("   free(ptr);\n");
    printf("   *ptr = 42;  // 使用已释放的内存\n");
    printf("   可能破坏新分配的数据\n\n");

    printf("3. 未初始化内存\n");
    printf("   int arr[10];\n");
    printf("   printf(\"%d\", arr[0]);  // 随机值\n");
    printf("   可能导致不确定行为\n\n");

    printf("4. 双重释放 (Double free)\n");
    printf("   free(ptr);\n");
    printf("   free(ptr);  // 释放两次\n");
    printf("   可能破坏内存分配器\n\n");

    printf("--- 内核调试工具 ---\n\n");

    printf("KASAN (Kernel Address Sanitizer):\n");
    printf("  检测越界访问和使用已释放内存\n");
    printf("  使用影子内存跟踪每字节状态\n");
    printf("  开销: 约 2-3 倍\n\n");

    printf("KMSAN (Kernel Memory Sanitizer):\n");
    printf("  检测未初始化内存使用\n");
    printf("  跟踪每字节的初始化状态\n\n");

    printf("KMEMLEAK:\n");
    printf("  检测内存泄漏\n");
    printf("  /sys/kernel/debug/kmemleak\n\n");

    printf("DEBUG_PAGEALLOC:\n");
    printf("  释放的页面标记为不可访问\n");
    printf("  使用已释放内存立即崩溃\n\n");

    printf("--- 使用 KASAN ---\n");
    printf("编译内核时启用:\n");
    printf("  CONFIG_KASAN=y\n");
    printf("  CONFIG_KASAN_INLINE=y\n\n");
    printf("运行时查看报告:\n");
    printf("  dmesg | grep KASAN\n");

    return 0;
}
```

*原来"调试"是"发现隐藏问题"的艺术。*

## 二

林小源在研究内存调试的过程中，理解了 KASAN 的原理。

KASAN 使用"影子内存"来跟踪每字节的状态。每次内存访问都会检查影子内存——如果访问了无效内存，KASAN 会立即报告。

*原来"影子"是"监控"的手段。*

---

## 三

林小源在观察内存调试的过程中，理解了调试工具的代价。

KASAN 会让内核变慢 2-3 倍——这是因为每次内存访问都需要额外检查。调试工具不适合在生产环境使用，但在开发阶段非常有用。

*原来"调试"有"代价"。*

---

### 道藏笔记

::: tip 内核启示
**内核提供多种内存调试工具。**

常见的内存 bug：
- 越界访问
- 使用已释放内存
- 未初始化内存
- 双重释放

调试工具：
- KASAN — 越界访问和使用已释放内存
- KMSAN — 未初始化内存
- KMEMLEAK — 内存泄漏
- DEBUG_PAGEALLOC — 使用已释放内存

KASAN 的原理：
- 使用影子内存跟踪每字节状态
- 每次访问检查影子内存
- 发现问题立即报告

*调试工具是"照妖镜"——让隐藏的 bug 无处遁形。*
:::
