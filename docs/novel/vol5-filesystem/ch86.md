# 第八十六章：挂载之道

<CultivationRealm realm="斩灵期" />

> **涉及内核源码：** <KernelSourceLink path="fs/namespace.c" line="do_mount" />

## 一

林小源在森林中发现了一个关键操作：挂载。

文件系统必须"挂载"到目录树上才能被访问。挂载把一个文件系统的根目录连接到另一个文件系统的某个目录上——这个目录叫"挂载点"。

```c:playground:mount — 挂载文件系统
#include <stdio.h>

/*
 * 挂载的概念：
 *
 *   /dev/sda1 (ext4) → 挂载到 /
 *   /dev/sdb1 (ext4) → 挂载到 /home
 *   tmpfs → 挂载到 /tmp
 *   proc → 挂载到 /proc
 *
 * 挂载后：
 *   /home/user/file.txt
 *   实际访问 /dev/sdb1 上的 file.txt
 *
 * mount 系统调用：
 *   mount("/dev/sdb1", "/home", "ext4", 0, NULL)
 *
 * mount 命令：
 *   mount -t ext4 /dev/sdb1 /home
 *   mount -t tmpfs tmpfs /tmp
 *
 * 挂载点：
 *   原来目录的内容被"遮盖"
 *   新文件系统的根目录替代原目录
 *   umount 后原目录内容恢复
 */

int main() {
    printf("=== mount — 挂载文件系统 ===\n\n");

    printf("挂载示例:\n");
    printf("  /dev/sda1 (ext4) → /\n");
    printf("  /dev/sdb1 (ext4) → /home\n");
    printf("  tmpfs → /tmp\n");
    printf("  proc → /proc\n");
    printf("  sysfs → /sys\n\n");

    printf("挂载后的目录树:\n");
    printf("  /\n");
    printf("  ├── bin/\n");
    printf("  ├── etc/\n");
    printf("  ├── home/  ← /dev/sdb1\n");
    printf("  │   └── user/\n");
    printf("  │       └── file.txt\n");
    printf("  ├── proc/  ← procfs\n");
    printf("  ├── sys/   ← sysfs\n");
    printf("  └── tmp/   ← tmpfs\n\n");

    printf("--- mount 系统调用 ---\n");
    printf("mount(source, target, fstype, flags, data)\n");
    printf("  source: 设备路径（如 /dev/sdb1）\n");
    printf("  target: 挂载点（如 /home）\n");
    printf("  fstype: 文件系统类型（如 ext4）\n");
    printf("  flags: 挂载标志（如 MS_RDONLY）\n\n");

    printf("--- 挂载标志 ---\n");
    printf("MS_RDONLY: 只读挂载\n");
    printf("MS_NOEXEC: 禁止执行\n");
    printf("MS_NOSUID: 忽略 setuid\n");
    printf("MS_NODEV: 禁止设备文件\n\n");

    printf("--- 绑定挂载 ---\n");
    printf("mount --bind /src /dst\n");
    printf("  把 /src 挂载到 /dst\n");
    printf("  两个路径指向同一文件系统\n\n");

    printf("--- 命名空间 ---\n");
    printf("不同进程可以有不同的挂载表\n");
    printf("容器使用 mount 命名空间隔离\n");

    return 0;
}
```

*原来"挂载"是"连接"两个世界的桥梁。*

---

## 二

林小源在研究挂载的过程中，理解了挂载点的"遮盖"效应。

当文件系统挂载到一个目录时，原来目录的内容被"遮盖"——用户看到的是新文件系统的根目录。卸载后，原来的内容恢复。

*原来"挂载"是"覆盖"。*

---

## 三

林小源在观察挂载的过程中，理解了 mount 命名空间的作用。

不同进程可以有不同的挂载表——这是容器隔离的基础。容器内的进程看到的文件系统与宿主机不同。

*原来"隔离"从"挂载"开始。*

::: tip 内核启示
**挂载把文件系统连接到目录树。**

- `mount(source, target, fstype, flags, data)`

- `MS_RDONLY` — 只读
- `MS_NOEXEC` — 禁止执行

- 不同进程可以有不同的挂载表
- 容器使用 mount 命名空间隔离

*挂载是"桥梁"——连接设备和目录树。*
