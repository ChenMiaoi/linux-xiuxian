# 第一百七十八章：宽限期

<CultivationRealm realm="大乘期" />

> **涉及内核源码：** <KernelSourceLink path="kernel/rcu/tree.c" />

## 一

林小源在读取侧临界区的基础上，理解了宽限期 (Grace Period) 的概念。

宽限期是 RCU 的核心——写入者更新指针后，必须等待一个宽限期才能释放旧数据。宽限期保证所有在更新前进入临界区的读者都已离开。

```c:playground:宽限期 — RCU 的核心
#include <stdio.h>
#include <stdlib.h>

/*
 * 宽限期 (Grace Period):
 *
 * 定义:
 *   从 rcu_assign_pointer() 到可以 free() 的时间段
 *   等待所有在更新前进入临界区的读者离开
 *
 * 时间线:
 *   T1: 写入者更新指针
 *   T2: 读者 A 进入临界区
 *   T3: 读者 B 进入临界区
 *   T4: 读者 A 离开临界区
 *   T5: 读者 B 离开临界区
 *   T6: 宽限期结束 (所有在 T1 前进入的读者已离开)
 *   T7: 写入者可以释放旧数据
 *
 * synchronize_rcu():
 *   阻塞等待宽限期结束
 *   不能在中断上下文使用
 *
 * call_rcu():
 *   异步等待宽限期
 *   注册回调函数
 *   可以在中断上下文使用
 *
 * 内核实现:
 *   检测上下文切换
 *   每个 CPU 都经历过静止状态
 *   宽限期结束
 */

/* 模拟宽限期 */
struct grace_period {
    int started;
    int completed;
    int readers_waiting; /* 仍在临界区的读者数 */
};

void gp_init(struct grace_period *gp) {
    gp->started = 1;
    gp->completed = 0;
    gp->readers_waiting = 0;
}

void gp_reader_enter(struct grace_period *gp) {
    gp->readers_waiting++;
}

void gp_reader_leave(struct grace_period *gp) {
    gp->readers_waiting--;
    if (gp->readers_waiting == 0 && gp->started) {
        gp->completed = 1;
    }
}

int gp_is_complete(struct grace_period *gp) {
    return gp->completed;
}

int main() {
    printf("=== 宽限期 — RCU 的核心 ===\n\n");

    struct grace_period gp;
    gp_init(&gp);

    printf("--- 时间线 ---\n");
    printf("T1: 写入者更新指针\n");
    gp_reader_enter(&gp); /* 读者进入 */
    printf("T2: 读者进入临界区\n");

    printf("T3: 写入者等待宽限期...\n");
    printf("  宽限期完成? %s\n", gp_is_complete(&gp) ? "是" : "否");

    gp_reader_leave(&gp); /* 读者离开 */
    printf("T4: 读者离开临界区\n");
    printf("  宽限期完成? %s\n", gp_is_complete(&gp) ? "是" : "否");

    printf("\n--- synchronize_rcu ---\n");
    printf("特点:\n");
    printf("  阻塞等待\n");
    printf("  不能在中断上下文使用\n");
    printf("  简单可靠\n\n");
    printf("用法:\n");
    printf("  更新指针\n");
    printf("  synchronize_rcu()\n");
    printf("  释放旧数据\n\n");

    printf("--- call_rcu ---\n");
    printf("特点:\n");
    printf("  异步等待\n");
    printf("  可以在中断上下文使用\n");
    printf("  回调函数\n\n");
    printf("用法:\n");
    printf("  更新指针\n");
    printf("  call_rcu(&head, callback)\n");
    printf("  // 宽限期后自动调用 callback\n\n");

    printf("--- 宽限期检测 ---\n");
    printf("方法:\n");
    printf("  检测上下文切换\n");
    printf("  每个 CPU 经历静止状态\n\n");
    printf("静止状态:\n");
    printf("  CPU 不在 RCU 读取临界区\n");
    printf("  上下文切换、空闲等\n\n");

    printf("--- 性能影响 ---\n");
    printf("synchronize_rcu:\n");
    printf("  可能阻塞毫秒级\n");
    printf("  适合进程上下文\n\n");
    printf("call_rcu:\n");
    printf("  不阻塞\n");
    printf("  适合中断上下文\n");

    return 0;
}
```

*原来"宽限期"是"安全释放"的"保障"。*

---

## 二

林小源在研究宽限期的过程中，理解了 synchronize_rcu 和 call_rcu 的区别。

synchronize_rcu 阻塞等待宽限期结束，适合进程上下文。call_rcu 注册回调函数，宽限期结束后自动调用，适合中断上下文。

*原来"异步"是"中断"的"选择"。*

---

## 三

林小源在观察宽限期检测的过程中，理解了静止状态 (Quiescent State) 的概念。

静止状态是 CPU 不在 RCU 读取临界区的状态。上下文切换、空闲都是静止状态。当所有 CPU 都经历过静止状态，宽限期结束。

*原来"静止状态"是"宽限期"的"里程碑"。*

---

### 道藏笔记

::: tip 内核启示
**宽限期保证旧数据安全释放。**

宽限期定义：
- 从更新指针到可以释放旧数据的时间段
- 等待所有在更新前进入临界区的读者离开

等待方式：
- synchronize_rcu — 阻塞等待
- call_rcu — 异步等待（回调函数）

静止状态：
- CPU 不在 RCU 读取临界区
- 上下文切换、空闲
- 所有 CPU 经历后宽限期结束

*宽限期是保障——等待读者离开，安全释放旧数据。*
:::
