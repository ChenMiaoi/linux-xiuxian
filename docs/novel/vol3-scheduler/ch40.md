# 第四十章：优先级

<CultivationRealm realm="结丹中期" />

> **涉及内核源码：** <KernelSourceLink path="kernel/sched/core.c" line="set_user_nice" />

## 一

林小源在研究调度的过程中，理解了"优先级"的层次。

Linux 内核中有三种优先级：
- **nice 值** — 用户态可见的优先级，范围 -20 到 19
- **prio 值** — 内核内部的优先级，范围 0 到 139
- **rt_priority** — 实时优先级，范围 1 到 99

```c:playground:优先级的层次
#include <stdio.h>

/*
 * Linux 优先级的三种表示：
 *
 * 1. nice 值: -20 ~ 19
 *    用户态可见，值越小优先级越高
 *    普通进程使用 nice 值
 *
 * 2. 内核 prio: 0 ~ 139
 *    0 ~ 99:  实时进程
 *    100 ~ 139: 普通进程 (100 + nice)
 *
 * 3. rt_priority: 1 ~ 99
 *    实时进程的优先级
 *    值越大优先级越高
 *
 * 转换关系：
 *   普通进程: prio = 120 + nice
 *   实时进程: prio = 99 - rt_priority
 */

#define MAX_RT_PRIO 100
#define DEFAULT_PRIO 120

/* nice 值到权重的映射 */
int nice_to_weight(int nice) {
    static int weights[] = {
        88761, 71755, 56483, 46273, 36291,
        29154, 23254, 18705, 14949, 11916,
         9548,  7620,  6100,  4904,  3906,
         3121,  2501,  1991,  1586,  1277,
         1024,   820,   655,   526,   423,
          335,   272,   215,   172,   137,
          110,    87,    70,    56,    45,
           36,    29,    23,    18,    15,
    };
    return weights[nice + 20];
}

int main() {
    printf("=== 优先级的层次 ===\n\n");

    printf("--- 普通进程的优先级 ---\n");
    printf("%-6s %-8s %-10s %-12s\n", "nice", "prio", "权重", "调度类");
    printf("%-6s %-8s %-10s %-12s\n", "---", "---", "---", "---");

    int nices[] = { -20, -10, 0, 5, 10, 19 };
    int nr = sizeof(nices) / sizeof(nices[0]);

    for (int i = 0; i < nr; i++) {
        int nice = nices[i];
        int prio = DEFAULT_PRIO + nice;
        int weight = nice_to_weight(nice);
        printf("%-6d %-8d %-10d %-12s\n",
               nice, prio, weight, "CFS (fair)");
    }

    printf("\n--- 实时进程的优先级 ---\n");
    printf("%-14s %-6s %-12s\n", "rt_priority", "prio", "调度类");
    printf("%-14s %-6s %-12s\n", "---", "---", "---");

    int rt_prios[] = { 99, 50, 1 };
    int nr_rt = sizeof(rt_prios) / sizeof(rt_prios[0]);

    for (int i = 0; i < nr_rt; i++) {
        int rt = rt_prios[i];
        int prio = MAX_RT_PRIO - 1 - rt;
        printf("%-14d %-6d %-12s\n", rt, prio, "RT (FIFO/RR)");
    }

    printf("\n--- 优先级的转换 ---\n");
    printf("普通进程:\n");
    printf("  prio = 120 + nice\n");
    printf("  nice -20 → prio 100 (最高)\n");
    printf("  nice  0  → prio 120 (默认)\n");
    printf("  nice  19 → prio 139 (最低)\n\n");
    printf("实时进程:\n");
    printf("  prio = 99 - rt_priority\n");
    printf("  rt_priority 99 → prio 0 (最高)\n");
    printf("  rt_priority 1  → prio 98 (最低)\n");

    printf("\n--- 调度类的优先级 ---\n");
    printf("stop > dl > rt > fair > idle\n");
    printf("  stop:  不可抢占，用于 CPU hotplug\n");
    printf("  dl:    Deadline 调度器\n");
    printf("  rt:    实时调度器 (FIFO/RR)\n");
    printf("  fair:  CFS (普通进程)\n");
    printf("  idle:  idle 进程\n");

    return 0;
}
```

*原来优先级有三种"语言"。*

## 二

林小源在研究优先级的过程中，理解了 nice 值与权重的关系。

nice 值每增加 1，进程获得的 CPU 时间大约减少 10%。这个关系不是线性的——权重表是一个精心设计的等比数列，保证了 nice 值的差异在 CPU 时间分配上的感知一致性。

*原来 nice 值的设计考虑了人对"公平"的感知。*

林小源还发现了一个有趣的细节：用户态进程可以通过 `nice()` 系统调用修改自己的 nice 值，但只能增加（降低优先级），不能减少（提高优先级）。只有 root 权限才能减少 nice 值。

*原来"降低自己"是自由的，"提高自己"需要特权。*

---

## 三

林小源在观察优先级的过程中，注意到了一个现象。

某些进程的 nice 值被设置得很低（如 -20），但它们的实际 CPU 使用率并不高。这是因为 CFS 的公平性保证——即使 nice 值很低，如果进程大部分时间在睡眠中，它也不会消耗太多 CPU 时间。

*原来 nice 值只在"竞争"时才起作用。*

这让林小源理解了优先级的本质：优先级不是"保证你获得多少 CPU"，而是"当 CPU 竞争激烈时，谁先获得 CPU"。

### 道藏笔记

::: tip 内核启示
**Linux 有三种优先级表示。**

nice 值（用户态）：
- 范围：-20 ~ 19
- 值越小优先级越高
- 每增加 1，CPU 时间约减少 10%
- 只有 root 能降低 nice 值（提高优先级）

内核 prio：
- 范围：0 ~ 139
- 0 ~ 99：实时进程
- 100 ~ 139：普通进程（`prio = 120 + nice`）

rt_priority（实时进程）：
- 范围：1 ~ 99
- 值越大优先级越高
- `prio = 99 - rt_priority`

权重表（`sched_prio_to_weight[]`）：
- 等比数列，保证 nice 值的差异在 CPU 时间上感知一致
- nice 0 = 1024（基准）
- nice -20 = 88761
- nice 19 = 15

*优先级不是"保证"，是"竞争"时的优势。*
:::
