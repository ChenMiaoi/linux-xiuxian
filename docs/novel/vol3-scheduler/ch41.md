# 第四十一章：运行队列

<CultivationRealm realm="结丹中期" />

> **涉及内核源码：** <KernelSourceLink path="kernel/sched/sched.h" line="struct rq" />

## 一

林小源在研究调度器的过程中，发现了一个关键的数据结构：运行队列（runqueue）。

每个 CPU 都有自己的运行队列——`struct rq`。它是调度器的"工作台"，包含了该 CPU 上所有可运行进程的信息。

```c:playground:运行队列 — per-CPU 的调度器
#include <stdio.h>
#include <string.h>

/*
 * 运行队列 (struct rq) 是 per-CPU 的：
 * 每个 CPU 都有自己的运行队列
 * 避免了多核之间的锁竞争
 *
 * struct rq 的关键字段：
 *   nr_running    — 可运行进程数
 *   cfs           — CFS 运行队列（红黑树）
 *   rt            — RT 运行队列
 *   dl            — Deadline 运行队列
 *   curr          — 当前运行的进程
 *   idle          — idle 进程
 *   clock         — 队列时钟
 *
 * per-CPU 设计的好处：
 *   - 减少锁竞争
 *   - 缓存亲和性
 *   - NUMA 感知
 */

struct cfs_rq {
    int nr_running;
    unsigned long min_vruntime;
};

struct rq {
    int cpu;
    int nr_running;
    struct cfs_rq cfs;
    int curr_pid;
    int idle_pid;
    unsigned long clock;
};

int main() {
    printf("=== 运行队列 — per-CPU 调度器 ===\n\n");

    /* 模拟 4 个 CPU 的运行队列 */
    struct rq rqs[4];

    for (int i = 0; i < 4; i++) {
        rqs[i].cpu = i;
        rqs[i].nr_running = 0;
        rqs[i].cfs.nr_running = 0;
        rqs[i].curr_pid = 0;
        rqs[i].idle_pid = i;  /* 每个 CPU 有自己的 idle */
        rqs[i].clock = 0;
    }

    /* 分配进程到不同的运行队列 */
    rqs[0].nr_running = 5;
    rqs[0].cfs.nr_running = 4;
    rqs[0].curr_pid = 100;

    rqs[1].nr_running = 3;
    rqs[1].cfs.nr_running = 2;
    rqs[1].curr_pid = 200;

    rqs[2].nr_running = 8;
    rqs[2].cfs.nr_running = 7;
    rqs[2].curr_pid = 300;

    rqs[3].nr_running = 1;
    rqs[3].cfs.nr_running = 0;
    rqs[3].curr_pid = 0;  /* idle */

    printf("各 CPU 的运行队列状态：\n");
    printf("%-6s %-12s %-10s %-10s\n", "CPU", "nr_running", "cfs_running", "curr");
    printf("%-6s %-12s %-10s %-10s\n", "---", "---", "---", "---");

    for (int i = 0; i < 4; i++) {
        printf("%-6d %-12d %-10d %-10s\n",
               rqs[i].cpu, rqs[i].nr_running,
               rqs[i].cfs.nr_running,
               rqs[i].curr_pid == 0 ? "idle" : "PID...");
    }

    printf("\n--- per-CPU 设计的优势 ---\n");
    printf("1. 减少锁竞争：每个 CPU 只访问自己的运行队列\n");
    printf("2. 缓存亲和性：进程倾向于在同一个 CPU 上运行\n");
    printf("3. NUMA 感知：进程倾向于在本地 NUMA 节点上运行\n\n");

    printf("--- 运行队列的操作 ---\n");
    printf("enqueue_task():   把进程加入运行队列\n");
    printf("dequeue_task():   把进程从运行队列移除\n");
    printf("pick_next_task(): 选择下一个运行的进程\n");
    printf("scheduler_tick(): 时钟中断时更新运行队列\n");

    return 0;
}
```

*原来每个 CPU 都有自己的"工作台"。*

---

## 二

林小源在研究运行队列的过程中，理解了 per-CPU 设计的重要性。

在多核系统中，如果所有 CPU 共享一个运行队列，锁竞争会成为性能瓶颈。per-CPU 运行队列避免了这个问题——每个 CPU 只需要访问自己的运行队列，不需要加锁（除了特殊情况下的负载均衡）。

*原来"分而治之"是多核调度的核心思想。*

但 per-CPU 设计也带来了新的问题：如果某些 CPU 的运行队列很"重"（进程多），而另一些 CPU 的运行队列很"轻"（进程少），系统整体的利用率就不高。这就是负载均衡需要解决的问题。

---

## 三

林小源在观察运行队列的过程中，注意到了一个细节。

运行队列中不仅有 CFS 的红黑树，还有 RT 运行队列和 Deadline 运行队列。每种调度类都有自己的运行队列，调度器按优先级依次检查：先检查 RT，再检查 CFS，最后检查 idle。

*原来运行队列是"分层"的。*

### 道藏笔记

::: tip 内核启示
**运行队列（`struct rq`）是 per-CPU 的调度器核心数据结构。**

运行队列的关键字段：
- `nr_running` — 可运行进程数
- `cfs` — CFS 运行队列（包含红黑树）
- `rt` — RT 运行队列
- `dl` — Deadline 运行队列
- `curr` — 当前运行的进程
- `idle` — idle 进程
- `clock` — 队列时钟

per-CPU 设计的优势：
- 减少锁竞争
- 缓存亲和性
- NUMA 感知

运行队列的操作：
- `enqueue_task()` — 把进程加入运行队列
- `dequeue_task()` — 把进程从运行队列移除
- `pick_next_task()` — 选择下一个运行的进程
- `scheduler_tick()` — 时钟中断时更新运行队列

*运行队列是调度器的"工作台"——每个 CPU 有自己的工作台。*
:::
