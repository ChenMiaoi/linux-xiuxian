# 第三十九章：时间片

<CultivationRealm realm="结丹初期" />

> **涉及内核源码：** <KernelSourceLink path="kernel/sched/fair.c" line="sched_slice" />

## 一

林小源在研究 CFS 的过程中，理解了"时间片"的真正含义。

CFS 不使用固定的时间片。它使用"目标延迟"（target latency）——一个调度周期，在这个周期内，所有可运行的进程都会获得至少一次运行机会。每个进程的实际运行时间与其权重成正比。

```c:playground:时间片的分配
#include <stdio.h>

/*
 * CFS 的时间片分配：
 *
 * target_latency = 目标延迟（调度周期）
 *   通常为 6ms（可配置）
 *   如果进程数 > target_latency / min_granularity，
 *   则 target_latency = 进程数 × min_granularity
 *
 * 进程的时间片：
 *   slice = target_latency × (weight_i / total_weight)
 *
 * 例如：
 *   target_latency = 6ms
 *   进程 A: weight = 1024 (nice 0)
 *   进程 B: weight = 1024 (nice 0)
 *   total_weight = 2048
 *   A 的时间片 = 6ms × (1024/2048) = 3ms
 *   B 的时间片 = 6ms × (1024/2048) = 3ms
 */

#define TARGET_LATENCY 6000000  /* 6ms = 6,000,000 ns */
#define MIN_GRANULARITY 750000  /* 0.75ms = 750,000 ns */

struct sched_entity {
    int pid;
    char comm[16];
    int nice;
    int weight;
};

int nice_to_weight(int nice) {
    static int weights[] = {
        88761, 71755, 56483, 46273, 36291,
        29154, 23254, 18705, 14949, 11916,
         9548,  7620,  6100,  4904,  3906,
         3121,  2501,  1991,  1586,  1277,
         1024,   820,   655,   526,   423,
          335,   272,   215,   172,   137,
          110,    87,    70,    56,    45,
           36,    29,    23,    18,    15,
    };
    return weights[nice + 20];
}

int main() {
    printf("=== 时间片的分配 ===\n\n");

    struct sched_entity procs[] = {
        { 100, "shell",   0, 0 },
        { 200, "batch",   5, 0 },
        { 300, "vim",     0, 0 },
    };
    int nr = sizeof(procs) / sizeof(procs[0]);

    /* 计算权重 */
    int total_weight = 0;
    for (int i = 0; i < nr; i++) {
        procs[i].weight = nice_to_weight(procs[i].nice);
        total_weight += procs[i].weight;
    }

    /* 计算 target_latency */
    int target_latency = TARGET_LATENCY;
    if (nr > target_latency / MIN_GRANULARITY) {
        target_latency = nr * MIN_GRANULARITY;
    }

    printf("目标延迟 (target_latency): %d ns (%.2f ms)\n",
           target_latency, target_latency / 1000000.0);
    printf("最小粒度 (min_granularity): %d ns (%.2f ms)\n\n",
           MIN_GRANULARITY, MIN_GRANULARITY / 1000000.0);

    printf("%-8s %-6s %-8s %-12s\n", "进程", "nice", "权重", "时间片");
    printf("%-8s %-6s %-8s %-12s\n", "---", "---", "---", "---");

    for (int i = 0; i < nr; i++) {
        unsigned long slice = (unsigned long)target_latency *
                              procs[i].weight / total_weight;
        printf("%-8s %-6d %-8d %-10.2f ms\n",
               procs[i].comm, procs[i].nice, procs[i].weight,
               slice / 1000000.0);
    }

    printf("\n--- 唤醒抢占 ---\n");
    printf("当一个进程从睡眠中醒来时：\n");
    printf("  1. 它的 vruntime 被调整为 min_vruntime\n");
    printf("  2. 如果它的 vruntime < 当前运行进程的 vruntime\n");
    printf("  3. 设置 TIF_NEED_RESCHED 标志\n");
    printf("  4. 当前进程被抢占\n\n");

    printf("--- 时间片用完 ---\n");
    printf("当进程的时间片用完时：\n");
    printf("  1. scheduler_tick() 更新 vruntime\n");
    printf("  2. 检查是否需要抢占\n");
    printf("  3. 如果有更优的进程，设置 TIF_NEED_RESCHED\n");
    printf("  4. 在返回用户态时调用 schedule()\n");

    return 0;
}
```

*原来时间片不是固定的——它按权重分配。*

## 二

林小源在研究时间片的过程中，发现了一个关键的机制：**唤醒抢占**。

当一个进程从睡眠中醒来时，它的 `vruntime` 会被调整——设置为红黑树中最小的 `vruntime`。这保证了睡眠的进程不会因为积累了过多的 `vruntime` 而永远得不到调度。

更重要的是：如果醒来的进程的 `vruntime` 小于当前运行进程的 `vruntime`，内核会设置 `TIF_NEED_RESCHED` 标志，触发抢占。当前进程被暂停，醒来的进程立即获得 CPU。

*原来"醒来"比"继续运行"更有优势。*

这种设计是有道理的：交互式进程（如 shell、编辑器）大部分时间在睡眠中等待用户输入。当用户输入时，它们需要立即响应。唤醒抢占保证了交互式进程的低延迟。

## 三

林小源在观察时间片的过程中，理解了 CFS 的一个设计权衡。

时间片太短 → 频繁的上下文切换，开销大
时间片太长 → 响应延迟高，交互式进程卡顿

CFS 通过 `min_granularity` 来平衡这个权衡。`min_granularity` 是每个进程的最小运行时间——即使进程数再多，每个进程也至少运行 `min_granularity` 纳秒。

*原来"粒度"是调度器的"分辨率"。*

### 道藏笔记

::: tip 内核启示
**CFS 不使用固定时间片——按权重分配。**

时间片计算：
```
slice = target_latency × (weight_i / total_weight)
```

关键参数：
- `target_latency` — 目标延迟（调度周期），通常 6ms
- `min_granularity` — 最小粒度，通常 0.75ms
- `weight` — 进程权重（由 nice 值决定）

时间片用完时：
1. `scheduler_tick()` 更新 `vruntime`
2. 检查是否需要抢占
3. 设置 `TIF_NEED_RESCHED` 标志
4. 在返回用户态时调用 `schedule()`

唤醒抢占：
1. 醒来的进程 `vruntime` 被调整为 `min_vruntime`
2. 如果 `vruntime` < 当前进程的 `vruntime`，触发抢占
3. 保证交互式进程的低延迟

*时间片不是固定的——它是按权重分配的比例。*
:::
