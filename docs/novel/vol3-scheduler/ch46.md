# 第四十六章：Deadline

<CultivationRealm realm="结丹后期" />

> **涉及内核源码：** <KernelSourceLink path="kernel/sched/deadline.c" line="pick_next_task_dl" />

## 一

林小源在调度竞技场的深处，发现了第三种调度器：Deadline 调度器。

它比 RT 调度器更特殊——它不是按"优先级"调度，而是按"截止时间"调度。每个 Deadline 进程都有三个参数：
- **运行时间**（runtime）— 每个周期内需要的 CPU 时间
- **截止时间**（deadline）— 每个周期内的截止时刻
- **周期**（period）— 任务的周期

```c:playground:Deadline 调度器 — 时间之约
#include <stdio.h>

/*
 * Deadline 调度器的参数：
 *   runtime  — 每个周期内需要的 CPU 时间
 *   deadline — 每个周期内的截止时刻
 *   period   — 任务的周期
 *
 * 例如：视频解码器
 *   每 33ms 需要解码一帧 (30fps)
 *   解码需要 10ms 的 CPU 时间
 *   必须在 33ms 内完成
 *   → runtime=10ms, deadline=33ms, period=33ms
 *
 * Deadline 调度器的规则：
 *   截止时间最近的任务最先运行
 *   保证任务在截止时间前完成
 *   优先级：Deadline > RT > CFS
 */

struct dl_entity {
    int pid;
    char comm[16];
    unsigned long runtime;   /* 纳秒 */
    unsigned long deadline;  /* 纳秒 */
    unsigned long period;    /* 纳秒 */
    unsigned long dl_time;   /* 绝对截止时间 */
};

int main() {
    printf("=== Deadline 调度器 — 时间之约 ===\n\n");

    struct dl_entity dl_procs[] = {
        { 100, "video-dec",  10000000, 33000000, 33000000, 33000000 },
        { 200, "audio-dec",   5000000, 20000000, 20000000, 20000000 },
        { 300, "sensor",      2000000, 10000000, 10000000, 10000000 },
    };
    int nr = sizeof(dl_procs) / sizeof(dl_procs[0]);

    printf("Deadline 进程：\n");
    printf("%-6s %-12s %-10s %-10s %-10s\n",
           "PID", "COMM", "runtime", "deadline", "period");
    printf("%-6s %-12s %-10s %-10s %-10s\n",
           "---", "---", "---", "---", "---");

    for (int i = 0; i < nr; i++) {
        printf("%-6d %-12s %-8.1fms %-8.1fms %-8.1fms\n",
               dl_procs[i].pid, dl_procs[i].comm,
               dl_procs[i].runtime / 1000000.0,
               dl_procs[i].deadline / 1000000.0,
               dl_procs[i].period / 1000000.0);
    }

    printf("\n--- Deadline 调度的规则 ---\n");
    printf("1. 截止时间最近的任务最先运行\n");
    printf("2. 任务在截止时间前完成\n");
    printf("3. 如果无法满足截止时间，任务被拒绝\n\n");

    printf("--- 优先级层次 ---\n");
    printf("Deadline > RT > CFS > Idle\n\n");
    printf("Deadline 进程总是优先于 RT 进程\n");
    printf("RT 进程总是优先于 CFS 进程\n");
    printf("CFS 进程总是优先于 Idle 进程\n");

    printf("\n--- 可调度性测试 ---\n");
    printf("内核在任务入队时检查：\n");
    printf("  sum(runtime_i / period_i) ≤ 1\n");
    printf("  即所有任务的 CPU 需求总和不超过 100%%\n");
    printf("  如果超过，任务被拒绝入队\n");

    return 0;
}
```

*原来调度也可以"约法三章"。*

---

## 二

林小源在研究 Deadline 调度器的过程中，理解了它的设计哲学。

Deadline 调度器是为硬实时任务设计的——那些必须在截止时间前完成的任务。视频解码、音频处理、工业控制——这些任务不能容忍延迟。

*原来"时间"也可以成为调度的"契约"。*

林小源还发现了一个关键的机制：**可调度性测试**。当一个 Deadline 任务试图入队时，内核会检查所有任务的 CPU 需求总和是否超过 100%。如果超过，任务被拒绝——因为内核无法保证所有任务都能在截止时间前完成。

*原来"拒绝"也是一种"保护"。*

---

## 三

林小源在观察 Deadline 调度器的过程中，理解了三种调度器的定位。

CFS 追求"公平"，RT 追求"确定性"，Deadline 追求"时间保证"。它们不是替代关系，而是互补关系——每种调度器都有自己的适用场景。

*原来"多样性"是内核调度器的设计哲学。*

---

### 道藏笔记

::: tip 内核启示
**Deadline 调度器为硬实时任务提供时间保证。**

Deadline 任务的三个参数：
- `runtime` — 每个周期内需要的 CPU 时间
- `deadline` — 每个周期内的截止时刻
- `period` — 任务的周期

Deadline 调度器的规则：
1. 截止时间最近的任务最先运行
2. 保证任务在截止时间前完成
3. 可调度性测试：`sum(runtime_i / period_i) ≤ 1`

优先级层次：
- Deadline > RT > CFS > Idle

三种调度器的定位：
- CFS — 公平（普通进程）
- RT — 确定性（实时进程）
- Deadline — 时间保证（硬实时进程）

*Deadline 调度器是"时间的守护者"——它保证任务在截止时间前完成。*
:::
