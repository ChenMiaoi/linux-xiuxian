# 第四十九章：睡眠与唤醒

<CultivationRealm realm="结丹后期" />

> **涉及内核源码：** <KernelSourceLink path="kernel/sched/core.c" line="try_to_wake_up" />

## 一

林小源在观察进程状态转换的过程中，理解了"睡眠"和"唤醒"的机制。

进程不是一直在运行的——它大部分时间在睡眠中等待：等待 I/O 完成、等待信号、等待锁、等待用户输入。

```c:playground:睡眠与唤醒 — 状态转换
#include <stdio.h>

/*
 * 进程的状态：
 * TASK_RUNNING        — 可运行（在运行队列中或正在运行）
 * TASK_INTERRUPTIBLE  — 可中断睡眠（等待事件，可被信号唤醒）
 * TASK_UNINTERRUPTIBLE — 不可中断睡眠（等待事件，不可被信号唤醒）
 * __TASK_STOPPED      — 停止（收到 SIGSTOP）
 * EXIT_ZOMBIE         — 僵尸
 *
 * 睡眠的典型流程：
 *   1. 进程检查条件是否满足
 *   2. 条件不满足 → 设置状态为 TASK_INTERRUPTIBLE
 *   3. 调用 schedule() 让出 CPU
 *   4. 进程从运行队列中移除
 *   5. 等待事件发生
 *   6. 事件发生 → 唤醒进程
 *   7. 进程被放回运行队列
 *   8. 进程继续执行
 *
 * 唤醒的函数：try_to_wake_up()
 *   1. 设置进程状态为 TASK_RUNNING
 *   2. 把进程加入运行队列
 *   3. 如果目标 CPU 需要，触发调度
 */

#define TASK_RUNNING           0
#define TASK_INTERRUPTIBLE     1
#define TASK_UNINTERRUPTIBLE   2

struct task_struct {
    int pid;
    char comm[16];
    int state;
};

void sleep(struct task_struct *tsk) {
    tsk->state = TASK_INTERRUPTIBLE;
    printf("[PID %d] 进入睡眠状态\n", tsk->pid);
}

void wake_up(struct task_struct *tsk) {
    tsk->state = TASK_RUNNING;
    printf("[PID %d] 被唤醒\n", tsk->pid);
}

int main() {
    printf("=== 睡眠与唤醒 ===\n\n");

    struct task_struct proc = { 100, "my_proc", TASK_RUNNING };

    printf("初始状态: PID %d, state=%d (RUNNING)\n\n",
           proc.pid, proc.state);

    /* 进程睡眠 */
    sleep(&proc);
    printf("当前状态: PID %d, state=%d (INTERRUPTIBLE)\n\n",
           proc.pid, proc.state);

    /* 进程被唤醒 */
    wake_up(&proc);
    printf("当前状态: PID %d, state=%d (RUNNING)\n\n",
           proc.pid, proc.state);

    printf("--- 睡眠状态的区别 ---\n");
    printf("TASK_INTERRUPTIBLE:\n");
    printf("  - 可以被信号唤醒\n");
    printf("  - 等待 I/O、等待用户输入\n");
    printf("  - ps 中显示为 'S'\n\n");
    printf("TASK_UNINTERRUPTIBLE:\n");
    printf("  - 不能被信号唤醒\n");
    printf("  - 等待磁盘 I/O、等待锁\n");
    printf("  - ps 中显示为 'D'\n");
    printf("  - 不可杀死（kill -9 无效）\n\n");

    printf("--- 唤醒的过程 ---\n");
    printf("try_to_wake_up():\n");
    printf("  1. 设置进程状态为 TASK_RUNNING\n");
    printf("  2. 把进程加入运行队列\n");
    printf("  3. 如果目标 CPU 需要，触发调度\n");
    printf("  4. 进程被调度执行\n");

    return 0;
}
```

*原来"睡眠"是进程的"日常"。*

## 二

林小源在研究睡眠的过程中，理解了 `TASK_INTERRUPTIBLE` 和 `TASK_UNINTERRUPTIBLE` 的区别。

`TASK_INTERRUPTIBLE` — 可中断睡眠。进程在等待事件时，可以被信号唤醒。这适用于大多数情况：等待 I/O、等待用户输入、等待锁。

`TASK_UNINTERRUPTIBLE` — 不可中断睡眠。进程在等待事件时，不能被信号唤醒。这适用于关键的 I/O 操作：磁盘读写、页面调入。

*原来"睡眠"也有"深度"。*

林小源还发现了一个有趣的现象：如果一个进程处于 `TASK_UNINTERRUPTIBLE` 状态，即使是 `SIGKILL` 也无法杀死它。这就是为什么有时候 `kill -9` 不起作用——进程正在等待磁盘 I/O。

*原来"不可中断"也是"不可杀死"。*

---

## 三

林小源在观察唤醒的过程中，注意到了一个优化。

当进程被唤醒时，`try_to_wake_up()` 会尝试把进程放到"最合适的" CPU 上运行——通常是之前运行它的 CPU（利用缓存）或者空闲的 CPU。

*原来"唤醒"也需要"选择"。*

### 道藏笔记

::: tip 内核启示
**睡眠和唤醒是进程状态转换的核心机制。**

进程的状态：
- `TASK_RUNNING` — 可运行（在运行队列中）
- `TASK_INTERRUPTIBLE` — 可中断睡眠
- `TASK_UNINTERRUPTIBLE` — 不可中断睡眠
- `__TASK_STOPPED` — 停止（收到 `SIGSTOP`）
- `EXIT_ZOMBIE` — 僵尸

睡眠的流程：
1. 设置状态为 `TASK_INTERRUPTIBLE`
2. 调用 `schedule()` 让出 CPU
3. 进程从运行队列中移除
4. 等待事件发生
5. 事件发生 → 唤醒进程
6. 进程被放回运行队列

唤醒的流程（`try_to_wake_up()`）：
1. 设置进程状态为 `TASK_RUNNING`
2. 把进程加入运行队列
3. 选择最合适的 CPU
4. 如果需要，触发调度

*睡眠是进程的"日常"——大部分时间都在等待。*
:::
